Comptano — Design System & Handoff

Logiciel comptable OHADA — v1 · juillet 2026

1. Contexte produit

Comptano (développé par Walsia) est un ERP comptable multi-tenant conforme aux référentiels OHADA (SYSCOHADA Normal, SYSCOHADA SMT, SYCEBNL), destiné aux PME, ONG, associations et écoles. Le produit est en tout début de vie : seuls l'authentification, l'onboarding d'entreprise et l'administration des utilisateurs sont en place ; le moteur comptable (Phase 1) reste à construire. Ce document livre le système de design (tokens + composants, clair/sombre) qui doit porter le produit sur plusieurs années d'itérations.

Stack front : Angular (composants standalone, signals). Aucune librairie UI n'est imposée — tous les tokens et composants ci-dessous sont sur-mesure et à implémenter en CSS custom properties + composants Angular.

2. Principe d'implémentation

Tous les tokens sont des variables CSS définies sur :root pour le clair, et re-déclarées sous un sélecteur [data-theme="dark"] pour le sombre. Basculer de thème = poser data-theme="dark" sur <html> ou <body> (piloté par l'utilisateur, pas seulement prefers-color-scheme). Chaque composant ne référence que les tokens sémantiques (var(--bg), var(--accent)…), jamais une valeur brute — c'est ce qui permet au thème de changer sans toucher aux composants.

Couleur du logo : le monogramme "W" utilise var(--copper-200) en mode clair (teinte cuivre d'origine) et devient noir (#000000) en mode sombre — seule exception à la règle des tokens sémantiques, car c'est un élément de marque fixe.

6. Écrans couverts (v1)

  • Accueil non connecté — logo adaptatif, accroche, 2 actions (créer un compte / se connecter)
  • Création d'entreprise (onboarding) — stepper 3 étapes : Entreprise → Référentiel → Administrateur
  • Création d'utilisateur — modale, stepper 3 étapes : Informations (Nom / Post-nom / Prénom / email) → Rôle → Confirmation
  • Liste des utilisateurs (ADMIN) — recherche + chips de filtre par rôle + table triable + pagination
  • Tableau de bord — cards KPI + navigation conditionnée par rôle

Hors scope de ce document : écrans détaillés des phases 2 à 7 (facturation, achats/immobilisations, RH, gestion documentaire, états financiers, reporting) — le système de tokens/composants ci-dessus est conçu pour les anticiper (tables denses, statuts multi-étapes, chiffres tabulaires, upload/preview générique à construire au moment venu).

7. Ce qui reste à faire côté front

  • Traduire les tokens ci-dessus en variables CSS Angular globales (un seul fichier tokens.css chargé dans angular.json)
  • Construire les composants standalone correspondants (Button, Badge, Alert, Field, Table, Stepper, Modal…) en respectant strictement les tokens sémantiques, jamais de couleur en dur
  • Implémenter le toggle clair/sombre (attribut data-theme + persistance utilisateur, ex. localStorage)
  • Gérer l'expiration de session (heartbeat Keycloak) avec redirection automatique vers l'écran d'accueil
