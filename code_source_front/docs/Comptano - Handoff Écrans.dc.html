Comptano — Handoff développement

Modifications à apporter : écran Compte & écran Gestion des utilisateurs — juillet 2026

Ce document décrit quoi changer et pourquoi. Les maquettes de référence sont Comptano - Ecran Compte.dc.html (variante 2a) et Comptano - Gestion Utilisateurs.dc.html. Respecter les tokens du design system (anthracite/cuivre, clair/sombre).

A. Écran Compte

Refonte complète de l'ancien écran (profil + entreprise + référentiel empilés, bouton "Se déconnecter" perdu en bas). Nouvelle structure : barre supérieure + onglets Infos / Admin.

A.1 — Barre supérieure

  • À gauche : avatar rond aux initiales de l'utilisateur connecté (ex. « JD » pour John Doe), dégradé cuivre. Générer les initiales depuis nom[0] + prénom[0], en majuscules.
  • À côté : nom complet + ligne secondaire « entreprise · RÔLE ».
  • À droite : toggle de thème (clair/sombre) puis bouton Se déconnecter (le bouton n'est plus en bas de page).

A.2 — Onglets

OngletContenuVisibilité
InfosMon profil, Référentiel comptable, Mon entrepriseTous les rôles
AdminActions réservées admin : « Gestion des utilisateurs »ADMIN uniquement — masquer l'onglet pour les autres rôles

A.3 — Carte « Mon profil »

  • En-tête d'identité : avatar initiales (60px) + nom complet + poste (badge, ex. « Comptable principal ») + email.
  • Badge « Email vérifié » en haut à droite : pastille verte avec ✓ si emailVerified === true. Si non vérifié : badge orange « Email non vérifié » + action de renvoi.
  • Nom / Post-nom / Prénom présentés en mini-cartes (3 colonnes). Post-nom vide = tiret grisé.
Nouveau champ requis : poste (fonction de l'utilisateur dans l'entreprise) — à ajouter au modèle utilisateur back + formulaire de création/édition. Afficher un fallback neutre si null.

A.4 — Référentiel comptable & Entreprise (style KPI)

  • Référentiel : 3 cartes — « Référentiel actif » (texte : SYSCOHADA / Système Normal), « Classes » (nombre, chiffres tabulaires), « Comptes » (nombre).
  • Entreprise : mini-KPI pour Type / Pays / Devise ; Raison sociale et N° identification en lignes ; le N° d'identification doit passer à la ligne proprement (word-break) et non déborder.

B. Écran Gestion des utilisateurs

B.1 — Recherche globale changement clé

Aujourd'hui la recherche ne porte que sur le nom (+ un champ email séparé). La remplacer par un seul champ qui filtre sur nom, post-nom, prénom ET email simultanément.

  • Concaténer nom + postnom + prenom + email, comparaison insensible à la casse et aux accents.
  • Filtrage à la frappe (debounce ~200 ms si la liste vient du serveur).
  • Supprimer le second champ « Rechercher par email » et le bouton « Rechercher » (recherche live). Conserver les chips de filtre par rôle et par statut.

B.2 — Activation / Désactivation changement clé

Le bouton « Désactiver » / « Activer » doit déclencher un vrai flux avec confirmation et retour visuel :

  1. Clic → ouverture d'une boîte de confirmation (modale) :
    • Désactivation : titre « Désactiver l'utilisateur ? », message « [Nom] ne pourra plus se connecter tant que le compte reste désactivé. », bouton rouge « Désactiver ».
    • Activation : titre « Activer l'utilisateur ? », message « [Nom] pourra de nouveau se connecter… », bouton vert « Activer ».
    • Bouton secondaire « Annuler » qui ferme sans rien changer.
  2. Confirmation → appel API (PATCH statut) → à la réussite :
    • Toast en haut de l'écran : vert « [Nom] a été activé. » / neutre foncé « [Nom] a été désactivé. », avec bouton OK pour fermer (auto-dismiss ~4 s).
    • La ligne concernée clignote brièvement (vert pour activation, rouge pâle pour désactivation).
    • Le badge de statut bascule Actif ↔ Inactif et le bouton d'action s'inverse (Désactiver ↔ Activer, couleurs inversées).
  3. En cas d'échec API : toast d'erreur (rouge) et statut inchangé.
